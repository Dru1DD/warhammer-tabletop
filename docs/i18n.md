# Languages

The interface comes in **English, Ukrainian, Polish and Russian**. Everything the player reads is translated: screens and
panels, the battle log and dice log, rule reasons from the engine, unit, weapon and Stratagem names and descriptions, the
AI's explanations, the tutorial and the post-battle coach.

## Choosing the language

`src/i18n/index.ts` picks the language once, when the page loads:

1. the choice saved by the switcher on the start screen (`localStorage` key `locale`);
2. the first of `navigator.languages` whose primary subtag is `en`, `ru`, `uk` or `pl`;
3. English.

Changing the language saves the choice and reloads the page, because the game data (unit names, weapon profiles, Stratagem
texts) is built at load time. `<html lang>` and the page title follow the language. The AI web worker gets the language as
its worker `name`, since a worker has no `localStorage`.

## How strings are written

The English text is the key: `tr('Round {round}/{maxRounds}', { round, maxRounds })`.

- `src/i18n/ru.ts`, `uk.ts` and `pl.ts` map each English key to its translation. English needs no catalog, and a missing key
  falls back to the English text.
- `{name}` placeholders are filled from the second argument. Keep every placeholder in every translation.
- Two different texts that read the same in English get a `|context` suffix, for example `tr('Save|alt')`. The suffix is
  never shown; only the catalogs see it.
- Russian, Ukrainian and Polish inflect nouns, so a sentence is translated whole instead of being glued from words. The coach
  (`src/ui/coach/text.ts`) picks a noun form with `plural()` (`Intl.PluralRules`) and a few case-specific keys such as
  `wound|acc` and `unit|gen`.
- Game logic never compares translated text. Dice steps carry `meta.kind`, so the UI recognises "hit", "wound" and so on
  without looking at their labels.

## Adding or changing a text

1. Write the English text at the call site with `tr()`.
2. Add the key to `ru.ts`, `uk.ts` and `pl.ts` (the files are sorted by key).
3. Run `npm test`. `src/i18n/i18n.test.ts` fails when a catalog lacks a key that the code uses, has an unused key, or has a
   translation with different placeholders.

## Adding a language

Add its code to `LOCALES` and `LOCALE_NAMES` in `src/i18n/index.ts`, a loader next to the others, and a catalog file with every
key. If the language has plural forms that differ from English, check `plural()` in the coach text.

## Tests

The tests run in Russian by default (`src/test-setup.ts`), so their text assertions are also a regression check on the
catalogs. `TEST_LOCALE=en npm test` runs them in another language: text assertions then fail by design, but an outcome
assertion (a winner, a wound count, a legality verdict) failing means some logic depends on the wording.

## Conventions

- **Identifiers are never translated.** Unit, datasheet, weapon, stratagem, keyword and faction ids (`'captain'`, `'commandReroll'`, `'adeptus_mechanicus'`), phase names, command types and the keys in saved games, army codes and the multiplayer protocol are language-independent. Only text shown to the player goes through `tr()`. A translation must not change any of them, and code must not branch on translated text.
- **Source strings are full English sentences** with `{placeholders}`. Do not build a sentence from pieces in code, because other languages reorder and inflect words. If a part must vary (a verb, a noun form), make it a separate key and pass it as a parameter, as `src/ui/coach/text.ts` does.
- **Keep game terms in English where players know them** (`Advance`, `Fall Back`, `Lethal Hits`, keyword names). Catalogs may put the English term in brackets after the translation, as the Russian original does.
- **One meaning per key.** Reuse a key only for the same meaning; use `tr('Text|context')` when two meanings share an English text.
- **Dates, numbers and quotes follow the language**: use `DECIMAL_MARK` and `quote()` from `src/i18n/index.ts`, not a hard-coded comma or «».
- Do not add an i18n library: `tr()` covers the app's needs and keeps the engine free of dependencies.

## Hardcoded text that is deliberately not translated

An audit of `src` (JSX text and `title`/`aria-label`/`placeholder` attributes, plus strings built in the engine) found only these English-only texts:

- the `WAAAGH!` button label in `src/App.tsx`;
- rules terms used as dice labels and notes: `D6`, `2D6`, `Hazard`, `Feel No Pain`, and the title `Deadly Demise: …`;
- `Repulsor Grid` in a wound note, the source name `Munitorum Field Manual (Dakkapedia)` in `src/game/data/points.ts`, and developer error messages (`throw new Error(...)`) that players should never see.

Everything else the player can read goes through `tr()`. Translation quality is not reviewed by native speakers yet: Ukrainian and Polish in particular need a proofreading pass.

## Known limits

- Texts that the engine stores in the game state (the battle log, dice log, unit names) are written in the language that was
  active when they were created. A save loaded under another language keeps its old log lines, and in an online game the
  guest's own engine writes the new lines in the guest's language.
- Short token labels (`Lt`, `IcS`, …) are abbreviations chosen per language.
